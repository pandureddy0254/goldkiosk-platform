# ADR 0001 — API documentation: first-party OpenAPI generation + Swagger UI (dev-only)

Date: 2026-07-02
Status: Accepted

## Context

Every GoldKiosk web API host (`GoldKiosk.Cloud.Api`, `GoldKiosk.Kiosk.Api`) needs
machine-readable API documentation and an interactive explorer for development, Postman
collection generation, and partner-facing contract review. The wiring must be defined once
and consumed identically by all web hosts — per the ServiceDefaults pattern — and must not
leak into desktop/windows projects (Kiosk.UI, Devices, Diagnostics), which never reference
ServiceDefaults.

Options considered:

1. **Full Swashbuckle** (`Swashbuckle.AspNetCore`): mature, but duplicates document
   generation that ASP.NET Core now provides first-party, and pulls in more surface than
   needed.
2. **First-party `Microsoft.AspNetCore.OpenApi` + `Swashbuckle.AspNetCore.SwaggerUI`**:
   document generation stays first-party (preferred per the dependency standard); the
   Swashbuckle package contributes only the static UI assets.
3. **Scalar / other UI**: capable, but the team asked for Swagger UI explicitly and it is
   the tool integrators know.

## Decision

- OpenAPI documents are generated by the **first-party `Microsoft.AspNetCore.OpenApi`**
  services (`AddOpenApi()` / `MapOpenApi()`), served at `/openapi/v1.json`.
- The interactive explorer is **Swagger UI** via `Swashbuckle.AspNetCore.SwaggerUI`
  (UI assets only — no Swashbuckle generation packages), served at `/swagger`.
- Both are wired once in `GoldKiosk.ServiceDefaults` (`AddDefaultOpenApi()` /
  `MapDefaultOpenApi()`); web API hosts call these alongside `AddServiceDefaults()`.
- **Exposure is Development-only.** `MapDefaultOpenApi()` no-ops outside Development.
  Exposing the document or UI in any deployed environment is a separate, explicit
  decision (future ADR) because Cloud.Api fronts financial/KYC endpoints and Kiosk.Api
  binds to localhost on hardened kiosk machines.
- Versions are pinned in `Directory.Packages.props`
  (`Microsoft.AspNetCore.OpenApi 10.0.9`, `Swashbuckle.AspNetCore.SwaggerUI 10.2.3`, and
  `Microsoft.OpenApi 2.9.0` as a direct pin overriding the vulnerable transitive `2.0.0` —
  GHSA-v5pm-xwqc-g5wc). Any project referencing `Microsoft.AspNetCore.OpenApi` directly
  must also reference `Microsoft.OpenApi`, since transitive pinning is disabled.
- License check: `Swashbuckle.AspNetCore.SwaggerUI` is MIT-licensed; all other packages
  are first-party Microsoft (MIT).

## Consequences

- One line each in a host's Program.cs lights up `/openapi/v1.json` + `/swagger` in dev;
  behaviour is uniform across cloud-api and kiosk-api.
- Endpoint metadata standards (`TypedResults`, declared `Produces`, versioned route
  groups `/api/v1/...`) feed the generated document directly — no duplicate annotations.
- ServiceDefaults carries the SwaggerUI package into all web hosts; it is dormant outside
  Development. Desktop projects are unaffected (they never reference ServiceDefaults).
- When API versioning lands (v2 route groups), `AddDefaultOpenApi` grows named documents
  per version — additive change, no host churn.
